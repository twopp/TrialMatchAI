# UIE 中文医疗实体抽取接入实施计划

## 目标

按照已确认的设计，将本地 `.venv-uie` 中的 `uie-medical-base` 作为独立 CPU 工作进程接入 TrialMatchAI 的试验条件预处理阶段，并在故障时显式回退到正则抽取。

## 实施步骤

1. 扩展实体配置和实体类别定义
   - 增加 `uie` 后端及独立 Python 路径、启动超时、请求超时、回退后端配置。
   - 为实体 schema 增加中文 UIE 提示词。
   - 为新增配置和 schema 编写测试。

2. 实现独立 UIE 工作程序
   - 使用逐行 JSON 协议通信。
   - CPU/FP32 加载 `uie-medical-base`，一次启动、多次服务。
   - 支持批量文本，返回实体位置、类别和置信度。
   - 保证诊断信息只进入标准错误。

3. 实现主项目 UIE 识别器
   - 延迟启动并复用工作进程。
   - 校验请求响应、应用置信度、转换现有 `EntityAnnotation`。
   - 保留跨类别重叠，清理同类别重复。
   - 安全关闭和回收子进程。

4. 实现故障回退与构建失效
   - 启动、超时、退出或协议错误时，当前及后续请求改用 regex。
   - 记录明确警告和运行状态。
   - 把 UIE 关键配置及工作程序版本加入 prepare 构建签名。
   - 使用假的工作程序测试成功、故障、超时和回退。

5. 启用 Mac 配置并验证
   - 在本地 `config.mac.json` 启用 UIE，不修改仓库默认后端。
   - 运行静态检查和完整测试。
   - 使用缓存模型运行中文实体冒烟测试。
   - 强制重新处理 `ALSC013AST2818` 的29条条件，检查实体和耗时。
   - 回归运行3名合成患者，确认检索、Qwen重排、DeepSeek评估和报告不受影响。

## 完成标准

- 主环境无需安装或导入 PaddlePaddle/PaddleNLP。
- 一次构建只加载一次 UIE 模型。
- 29条中文条件在5分钟内完成并保存实体。
- UIE故障能够清晰提示并自动回退正则。
- 全部自动化测试通过，现有端到端匹配继续成功。
